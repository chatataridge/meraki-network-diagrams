

I spent a minute looking at this and yes, the information is there and consumable. This is off of my home network and is a quick PoC. The links you see below are from my dashboard/network so you can't click them, but you can easily find/replace and do this for yours.

I can't find a direct topology API endpoint for Meraki - they do publish CDP/LLDP but here's a clever hack to get data from your web browser when there isn't an API for it.

Quick note: I didn't use Visio to output a drawing, instead I used Mermaid (diagrams as code… if you're not familiar, it's pretty slick).

Onwards…..

When you open the Topology screen in your browser, a GET is performed on this URL - open DevTools and look for this URL:

https://n127.dashboard.meraki.com/Home-switch/n/isCShc_b/manage/nodes/topology?from=network-wide+topology

If you look at the response tab, you'll see the data for the Topology page. If you scroll down, you can divine that the "topo" key gives you the network layout, and the "Mkijson.n.hash" gives you model, serial, etc.. (the data that you see on the diagram).

Unlike an API, this URL returns HTML and the topo/mjijson keys are in the payload of the HTML. You need to use regex/BeautifulSoup (or something similar) to extract the JSON elements. But, we have the data!

From there, it's pretty straightforward. To generate one drawing, I fed Claude the JSON objects and asked it to write a Python script that parses the topo and metadata. That's what created the picture above.

Ok, so Len wants to do this for 600 different networks, right? That's where the API can come in and cURL is your friend!


By looking at DevTools, I can see that the Topology page on Dashboard is generated on the local PC. It's a React component that's making these nice clickable diagrams. I know this because I can search for my firewall ('8111 Firewall') in the DevTools dump and I see it contained in JSON. If this was generated server-side, all I'd get back is an SVG. If the data is rendered on your machine, you can render it however you want.

From a browser flow perspective, your browser logs in to dashboard.meraki.com and gets an authentication cookie. Specifically, there are two of them - dash_auth and _session_id_for_n127. The presence of these two cookies (which are time-sensitive, not sure exactly how long they're good for) allows your browser to pass auth and do "stuff".

Any "thing" that has those cookie values can auth into your dashboard. There's a trick - we can capture the cURL request from your Chrome/Edge/Firefox browser and copy the tokens into a Python script. The request auth is contained in the headers, so you can right click on your request and choose Copy -> Copy as cURL Try it and paste the cURL command into a terminal, and boom - you'll see the raw HTML for your topology.

Now, this needs to be done reasonably quickly. Meraki dashboard rotates the tokens after X amount of minutes, but there's nothing that prevents us feeding that cURL cookie information into a Python requests script.

My workflow for something like this is to auth to the remote website in Chrome/Edge/whatever, copy the cURL information that shows the auth into a "curl.txt" file, un whatever I want to capture the site content to my local machine, then do a secondary script to process it into the format that I want.
So, here you go -
	1. Log in to Dashboard. Capture the URL(s) of the networks that you want to grab topology for (or use the API to programatically get the list) and put them in networks.txt
	2. Copy your cURL token to the curl.txt file
	3. Run the capture_topology.py script to download and parse the JSON for each network
	4. Run meraki_topo_to_mermaid.py to turn them into Mermaid diagrams (or whatever else you want)
Claude Opus 4.8 did the scripting so you should be able to easily use any LLM to change this to suit your workflow.
